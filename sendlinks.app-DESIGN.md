# Design System Inspired by send/links

## 1. Visual Theme & Atmosphere

send/links embodies a warm, approachable minimalism grounded in deliberate color-blocking and playful micro-interactions. The design prioritizes clarity and honesty through a restrained palette anchored by deep ink (`{colors.primary}` — `#1A1A1A`), paired with an energetic orange accent (`{colors.link}` — `#FF4D00`) and a sunny yellow highlight (`{colors.accent}` — `#FFE14D`). The atmosphere is intentionally handcrafted—hard shadows and slightly offset elements create depth through physical displacement rather than blur or gradation, evoking the tactile precision of print design. Every interaction feels considered; cards lift with crisp shadows, buttons respond with color-blocked depth, and the warm beige canvas (`{colors.canvas}` — `#F5F0E8`) establishes a calming, distraction-free environment. Typography is refined yet humanistic, layering serif headlines with a utility sans-body to balance authority with approachability.

**Key Characteristics**
- **Color-blocking depth**: Shadows are hard-edged, offset strokes—never soft blurs; depth arrives through displacement and color contrast
- **Warm-neutral foundation**: Beige, cream, and warm grey create a paper-like, organized feel
- **Accent restraint**: Primary orange and yellow are deployed sparingly for CTAs and highlights, ensuring they command attention when used
- **Serif + sans pairing**: Distinctive serif headlines (Instrument Serif) paired with a clean sans body (DM Sans) establish hierarchy and personality
- **Physical interaction model**: Cards and buttons respond with slight lifts and shadow shifts, mimicking tactile feedback
- **Accessible neutrals**: A carefully-graded body/muted/hairline text ramp ensures legibility across every surface

### Principles
- **Serif for authority**: Display and heading scales use Instrument Serif to establish presence and draw visual attention.
- **Negative tracking at scale**: Large display sizes (Display XL, Display MD) employ negative letter-spacing (`-1.6px`) to tighten letter fit and reinforce boldness.
- **Variable line heights**: Display uses generous line height (1.05–1.5) for breathing room; body defaults to 1.63 for comfortable reading; captions compress to 1.33 for density.
- **Weight as hierarchy**: Body text runs 400 (regular), emphasis uses 500 (medium), and select display runs 700 (bold) for additional impact.
- **Monospace for data**: Code roles use JetBrains Mono to signal technical content and ensure alignment in tables and snippets.

## 5. Layout Principles

### Spacing System
The system employs a base unit of `{spacing.xxs}` (4px) scaled in a proportional ladder:
- `{spacing.xxs}` (4px): Micro-adjustments, button padding refinements
- `{spacing.xs}` (8px): Tight spacing, small gaps between elements
- `{spacing.sm}` (12px): Standard small gap, label-to-input spacing
- `{spacing.md}` (16px): Default spacing, padding, standard gaps between sections
- `{spacing.lg}` (20px): Card padding, moderate section spacing
- `{spacing.xl}` (24px): Section headings, larger whitespace
- `{spacing.xxl}` (28px): Between major sections
- `{spacing.xxxl}` (32px): Large button padding, emphasis spacing
- `{spacing.section}` (40px): Section padding and gaps
- `{spacing.band}` (48px): Full-width band and footer padding

**Usage Context:**
- Button padding: `{spacing.xs}`–`{spacing.xxxl}`
- Card internal padding: `{spacing.lg}`
- Between cards: `{spacing.md}`–`{spacing.lg}`
- Section top/bottom padding: `{spacing.section}`–`{spacing.band}`

### Grid & Container
- **Max width**: Content remains centered and responsive; at 1280px+ breakpoint, max-width reaches 1200px
- **Column strategy**: The grid adapts from 2 columns (375px) to 4 columns (768px+)
- **Section pattern**: Full-width bands alternate with centered containers. Padding is applied to sections, not individual grid items.
- **Container padding**: Sections use symmetric padding with no additional horizontal padding on 375px (sides flush to viewport)

### Whitespace Philosophy
Whitespace is deliberate and generous, emphasizing clarity and calm. The system favors vertical breathing—sections are separated by `{spacing.band}` (48px) to create distinct visual zones. Horizontal padding within cards uses `{spacing.lg}` (20px) to keep content centered and readable. The warm canvas background (`{colors.canvas}` — `#F5F0E8`) eliminates the need for excessive layering; whitespace itself becomes a design element.

### Border Radius Scale
- `{rounded.none}` (0px): Sharp corners; used on featured cards, badges, and buttons
- `{rounded.xs}` (4px): Subtle rounding; buttons and default cards
- `{rounded.sm}` (6px): Slightly softer rounding; secondary card variants

### Border Widths
- Thin (`1px`): Default card borders, button borders, and standard dividers
- Medium (`2px`): Secondary button borders (large filled variant)

## 6. Depth & Elevation

| Level | Treatment | Use |
|---|---|---|
| Flat | No shadow; color only | Decorative featured cards, badges |
| Micro | `{colors.primary}` (`#1A1A1A`) `3px 3px 0px 0px` offset | Small buttons, accent states |
| Small | `{colors.primary}` (`#1A1A1A`) `4px 4px 0px 0px` offset | Standard buttons, default cards |
| Medium | `{colors.link}` (`#FF4D00`) `3px 3px 0px 0px` offset | Accent interactive states |
| Large | `{colors.primary}` (`#1A1A1A`) `6px 6px 0px 0px` offset | Elevated card hover, modal-like surfaces |

**Shadow Philosophy:**
The system employs a color-blocking elevation strategy rather than traditional blur-based shadows. All shadows are hard-edged, offset strokes that mimic the tactile effect of overlapping paper or card stock. Shadows always use the same color as the element's border or a brand accent color, creating visual consistency and reinforcing the physical metaphor. This approach eliminates the need for multiple shadow layers and creates a distinctive, print-like aesthetic that feels intentional and craft-oriented.

### Opacity Levels
- `0.05` (5%): Minimal hover state, almost imperceptible background tint
- `0.09` (9%): Subtle overlay tint
- `0.50` (50%): Medium opacity for disabled or secondary states
- `0.75` (75%): High opacity for strong visual presence
- `0.90` (90%): Near-opaque for strong emphasis

### Z-index / Layering
- `1`: Base layer (body, page content)
- `2`: Card overlays, slightly elevated surfaces
- `3`: Embedded interactive overlays
- `4`: Floating controls, secondary tooltips
- `5`: Primary modals, high-priority overlays
- `10`: Dropdown menus, sub-overlays
- `20`: Top-level dropdowns, secondary menus
- `50`: Toast notifications, system alerts

## 7. Do's and Don'ts

### Do
- **Use hard-edged shadows**: All depth comes from offset shadows in brand colors, never soft blur. Shadows should feel like physical displacement.
- **Leverage the warm neutral foundation**: Let `{colors.canvas}` (`#F5F0E8`) and `{colors.surface}` (`#FDFAF4`) do the visual work. Surfaces do not need decorative gradients or patterns.
- **Apply accent colors sparingly**: `{colors.link}` (`#FF4D00`) and `{colors.accent}` (`#FFE14D`) are reserved for CTAs, interactive states, and highlights. Overuse dilutes their impact.
- **Pair serif headlines with sans body**: Use Instrument Serif for Display and Headings; DM Sans for all body copy, navigation, and UI text. This pairing is the system's personality.
- **Maintain generous vertical spacing**: Section spacing of `{spacing.band}` (48px) creates distinct zones and prevents visual clutter.
- **Respect border radius consistency**: Apply `{rounded.xs}` (4px) to interactive elements (buttons, inputs) and `{rounded.sm}` (6px) to cards for subtle differentiation.
- **Ensure text contrast**: Always validate that text meets WCAG AA (4.5:1) on the surface it occupies. The `{colors.body}` and `{colors.muted}` scale is calibrated for accessibility.

### Don't
- **Avoid soft or blurred shadows**: Never use `blur()` or `drop-shadow()` for depth. Shadows must be hard-edged, offset strokes.
- **Don't invent new colors**: Stick to the extracted palette. Avoid tints, shades, or custom color mixes outside the defined roles.
- **Don't apply accent colors to body text**: `{colors.link}` and `{colors.accent}` are reserved for interactive states and calls-to-action. Body copy must use `{colors.body}` or `{colors.muted}`.
- **Don't overuse decorative accents**: The green (`{colors.accent-1}` — `#C8E6C9`) and blue (`{colors.accent-2}` — `#E3F2FD`) are decorative only; do not assign functional meaning to them.
- **Don't mix serif and sans inconsistently**: Maintain the serif-for-headings, sans-for-body rule. Monospace (JetBrains Mono) is reserved for code and technical data.
- **Don't collapse spacing aggressively on mobile**: Maintain vertical breathing even at small breakpoints. Section padding should adapt proportionally, not disappear.
- **Don't remove focus indicators**: Links and interactive elements must have a visible focus state (outline or shadow). Use `{colors.accent}` (`#FFE14D`) or a `2px solid` outline.
- **Don't apply buttons without borders**: All buttons include a `1px solid` border in `{colors.primary}` unless explicitly marked as "ghost" or "flat" (which the system does not currently define).

### Iteration Guide
1. **Color Blocking Over Blur**: Every shadow is a hard-edged offset stroke in a brand color. Avoid `box-shadow: 0 4px 8px rgba(...)` patterns. Use `box-shadow: {offset-color} Xpx Ypx 0px 0px` instead.
2. **Serif Headlines, Sans Body**: Instrument Serif for all Display and Heading roles; DM Sans for body, nav, buttons, and UI. Never mix serif in body copy.
3. **Accent Restraint**: `{colors.link}` (`#FF4D00`) and `{colors.accent}` (`#FFE14D`) are reserved for CTAs, interactive states, and deliberate highlights. Do not apply them to decorative or neutral content.
4. **Border Radius Precision**: Buttons and interactive elements use `{rounded.xs}` (4px); cards use `{rounded.sm}` (6px); featured cards use `{rounded.none}` (0px). Do not apply arbitrary values.
5. **Spacing Rhythm**: Section padding is `{spacing.section}` (40px) to `{spacing.band}` (48px). Do not reduce on mobile; maintain vertical breathing across all breakpoints.
6. **Text Color Hierarchy**: Use `{colors.primary}` for headings and primary content; `{colors.body}` for body text; `{colors.muted}` for secondary labels and captions. Do not use interactive colors for static text.
7. **Border Always Present**: All interactive components (buttons, cards, inputs) include a `1px solid` border in `{colors.primary}`. Borders are structural, not decorative.
8. **Opacity for Disabled States**: Disabled or secondary states use `opacity: 0.5` or `0.75`. Do not invent new colors for disabled states.
9. **Focus Indicators**: Links and buttons must have a visible focus state: `outline: 2px solid {colors.accent}` or equivalent shadow shift. Never remove focus outlines.
10. **Canvas as Foundation**: The warm beige canvas (`#F5F0E8`) is the primary reading surface. Let it breathe; do not layer excessive decorative elements or gradients on top.

## 10. Known Gaps

- **No semantic status colors**: The site does not expose error, success, warning, or info color roles in its markup. This system does not define a semantic color ramp; error/success states should default to visual patterns (text emphasis, icons) rather than color alone.
- **No interaction states for disabled elements**: Disabled button and form states were not captured in the extraction. Implement disabled states using opacity (`0.5`) and cursor changes; confirm contrast remains acceptable.
- **No dark mode / theme switching**: The extracted palette represents a single, light theme. No dark mode variant was observed or measured.
- **No gradients or decorative meshes**: The design system does not employ gradients, mesh backgrounds, or pattern fills. All depth and visual interest comes from color blocking and offset shadows.
- **Three unassigned accent colors**: `{colors.accent-1}` (`#C8E6C9` — green) and `{colors.accent-2}` (`#E3F2FD` — blue) have no measured functional role; they appear as decorative accents only. Do not assign semantic meaning to them.
- **No form validation feedback**: Form input validation states (error outline, success checkmark, etc.) were not observed in the extraction. Implement using text labels and icon cues rather than color changes alone.
- **No motion / animation timing**: Keyframe animations, transitions, and easing curves were not extracted. The system describes static state changes; animation behavior should follow platform defaults (e.g., 200ms ease-in-out for state shifts).
- **Limited interactive state coverage**: Only hover, focus, and active states were partially captured. Visited link states, loading states, and other stateful behaviors are not defined.
- **No component-specific spacing overrides**: Extracted padding values are specific to measured component variants. Other spacing contexts (grid gaps, list item spacing, etc.) were not systematically measured and should be inferred from the base spacing scale.
- **Pages behind authentication not visited**: The extraction covered 6 public pages. Authenticated dashboards, user settings, and private surfaces may employ additional component patterns or color roles not represented here.
